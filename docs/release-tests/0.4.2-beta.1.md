# Tests passed before KDF Reloaded 0.4.2-beta.1

> **Status: final.** The lab rows below ran on the build of the head `d5cb67d28` of the release branch.
> The two later merges into the release branch change only the pinned `url` library and the changelog:
> the code of the build is the same.

This page lists the tests that ran against the builds of this release before it was tagged: what
each one checked, on which build, and what came out of it.

**Testing level.** 0.4.2-beta.1 is a patch release with one change, for ARRR only: a shielded spend
signs each note with the key of the ZIP-32 scope the note belongs to, so the change that a Pirate
wallet of the same seed keeps on its internal address can be spent, and `my_balance` shows only
what can be spent. The tests cover that change, a regression of the ARRR wallet, and a short smoke
test; the full release matrix of 0.4.0-beta.1 is not repeated.

## ARRR: change on the internal address of a Pirate wallet of the same seed

Setup: closed lab network, mainnet ARRR and RIN on lab wallets. The ARRR seed is also used in a
Pirate wallet, which has sent a payment and kept its change on its internal Sapling address. Two
KDF Reloaded nodes (R-R). Run on the head `d5cb67d28` of the release branch, a release build. The contrast build is the official
`v0.4.1-beta.1` x86-64 asset, whose checksums and signature were verified. The same rows also passed
earlier on the head `f061d72bf` of the fix. Times are CET. The lab wallet was funded by a payment from
the Pirate daemon wallet to the wallet's internal address.

| Row | Result | What is checked |
| --- | --- | --- |
| Balance and spendable amount, 0.4.1-beta.1 | pass (reference) | on 0.4.1-beta.1, `my_balance` includes the note on the internal address, but a withdrawal that spends it is rejected at broadcast with `bad-sapling-bundle-authorization` (2026-11-25, 22:49 to 22:53) |
| Balance and spendable amount, the hotfix | pass | on the hotfix build, `my_balance` includes the note and the withdrawal that has to spend it is accepted (2026-11-26, 00:34 to 00:38); not compared with a figure from the Pirate wallet, only with the successful spend |
| Withdrawal | pass | a withdrawal with the internal-address note as input, to a `pirate1` address and of the maximum, is built, broadcast and mined, with the fee of 0.0001 ARRR (2026-11-26, 00:36 to 00:37) |
| Swap payment | pass | an R-R ARRR/RIN swap in which the ARRR payment can only come from that note completes on both sides (2026-11-26, 00:46 to 00:52). On 0.4.1-beta.1 the same swap failed: the maker's payment was rejected and the taker timed out (2026-11-25, 23:06 to 23:20) |

## ARRR: wallet regression

Setup: as above, on the hotfix build, 2026-11-26, 00:37 to 00:42.

| Row | Result | What is checked |
| --- | --- | --- |
| Deposit from a version-6 wallet | pass | a payment from a Pirate wallet that builds version-6 transactions to the node's `zs1` address is found and shown in the balance |
| Withdrawal to a `pirate1` address | pass | a withdrawal to a `pirate1` address pays the fee of 0.0001 ARRR (10,000 of the smallest unit) and is mined |
| Own change | pass | the change of that withdrawal, on the node's `zs1` address, is spendable in the next withdrawal |

## Smoke test

Setup: the hotfix build on a lab node.

| Row | Result | What is checked |
| --- | --- | --- |
